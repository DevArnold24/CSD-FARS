CSD ATTENDANCE - CLIENT QUICK START
===================================

You do not need to install Python, Git, Node.js, or database software.

For the illustrated installation and daily-use guide, open
CLIENT_QUICK_START.html in your browser. Install one server; give the other
computers its connection kit so everyone uses the same records.

1. Extract the complete official Windows Client Bundle to a normal folder on
   this laptop, outside OneDrive. Choose a new empty destination; do not extract
   over an old installation or copy its database, keys, or camera configuration.
2. Double-click START_HERE.cmd.
3. Choose Use on this computer for private use, or Share with computers on this
   network when this computer should host one database for your trusted LAN.
4. The first setup needs an internet connection and can take several minutes.
   Later starts work without internet.
5. Create your own Dean/admin account in the setup window. Password rules and
   a Show passwords option help you check your entry; mismatches can be fixed
   in the same window. Fresh setup creates no
   sample students, cameras, classes, or attendance records.
6. Keep the black server window open while using a foreground server.

If setup is interrupted, reopen the same launcher and follow its saved-progress
message. Do not reset files or create another administrator to get past an error.
Give your technician the displayed fixed code, or the correlation number in the
latest local .support\latest-result.json receipt. It contains no raw logs or
camera credentials and is never uploaded automatically.

If this server's trusted LAN address changes, stop the server and choose
Review a changed server network in START_HERE. Choose the intended trusted
connection explicitly. Restore preceding LAN configuration is a separate recovery
choice; Windows may ask approval to restore this installation's recorded rule.
After a completed refresh, give browser laptops the complete newly generated kit.

After signing in as Dean/admin, Setup Center lets you save Local only or Shared
LAN for the next interactive launch. It keeps the same accounts and database;
it does not change the running server. Finish sessions, stop the server, then
open START_HERE.cmd on that server computer and confirm its displayed choice.
Select a mode button to continue; closing the window starts nothing.
Windows network/security approvals still take place locally. A saved choice
does not change automatic startup: Stop and Disable any scheduled LAN task
separately before switching to local-only use. Setup Center can also export a
verified public connection kit once this server is running in configured LAN
mode. Do not bypass certificate warnings or use another server's kit.

Dean and IT Support accounts can open Network to see server adapters, traffic,
recent signed-in client addresses, saved camera checks, and Windows' remembered
devices. These observations do not start camera video. Remembered devices are
not a complete list of everything connected to your router or switch.

After LAN setup, Manage automatic startup offers optional startup before Windows
sign-in. It is off by default. Choose Enable explicitly, approve Windows as the
same installation owner, and enter that owner's Windows password locally.
Do not send passwords in chat. Enable schedules the next boot; use Start for
an immediate test. Keep the server powered on, awake, and plugged in.

The clean ZIP is the portable installer: use it for each fresh computer.
Do not copy an initialized application folder, database, keys, or scheduled task
to make another server. Give browser-only laptops the server's LAN_CLIENT_KIT.
See PORTABLE_QUICK_START.md for the choices and automatic-start controls.

To update this server, finish attendance and stop its foreground server, or use
Manage automatic startup > Stop for a scheduled server. Open START_HERE.cmd and
choose Update or recover. Choose the supplied update ZIP without extracting it,
review the version, then select Back up and apply update. Read the result before
starting the server again in its usual mode. Other laptops normally just refresh
their browsers; they do not install another server.

Updates need an approved update package for this installation. If the window
says publisher-approved updates are not available, keep using the current
version and ask the system owner for the supported upgrade procedure. Do not
overwrite the installed folder with a fresh-install ZIP. For an interrupted
update, the same Update or recover choice guides you through recovery first.

LAN sharing is optional. START_HERE checks the router connection and explains
which connection to choose when both Ethernet and Wi-Fi are connected. Select
the one on the same trusted router as the joining computers. It then explains
what to do in plain language. If Windows calls your trusted router Public, choose
Make this connection Private and approve the Windows prompt. For daily use, ask
the router owner to reserve the server address so the connection kit stays valid.
Use the current address is available for a setup check without a router login;
the address may change later.
CSD Attendance never configures Internet port forwarding.

Ignore the other CMD files unless the system owner or technician asks you to
use one for a check, recovery, or advanced LAN task.

If a red error appears, leave the folder unchanged and send the system owner a
clear photo of the complete message. Never disable Defender or SmartScreen and
never run reset, seed, or migration tools yourself. Use the guided Update or
recover choice for supplied updates; do not replace application files manually.

The included publisher public key checks supported update packages. It is not a
Windows Authenticode signature or proof of release approval or target-computer
qualification. Use only the bundle and updates approved by the system owner.
