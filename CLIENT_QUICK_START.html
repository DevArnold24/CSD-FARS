Server requirements: Windows on an Intel/AMD 64-bit computer, at least 6 GB free space, and internet access for the first setup. You do not need to install Python or database software. Camera performance is checked on this laptop after setup.

1 · SERVER LAPTOP

Install once

  1. Connect this laptop, the CCTV and the other computers to the same trusted router. A switch can connect their Ethernet cables to that router. An isolated switch-only LAN also works when each device already has a unique private IPv4 address in the same subnet. It needs no default gateway for local attendance; ask your network owner to configure the addresses. Setup does not assign addresses or change routes.
  2. Extract the complete supplied installer ZIP to a permanent local folder, outside OneDrive. Keep all its files together.
  3. In that folder, double-click START_HERE.cmd and choose Share with computers on this network. This opens guided LAN setup on first use and starts the server on later days.
  4. If more than one network is connected, choose the connection used by the other computers. Setup shows its name and address.
  5. Wait for the first setup, then create your Dean / administrator account. Use Show passwords if needed; you can correct a mismatch in the same window.

Use this same folder and Windows account on later days. Each separate server installation has its own records.

2 · SERVER LAPTOP

Complete the network steps

  1. If Windows calls your trusted router Public, choose Make this connection Private and approve the Windows prompt.
  2. For daily use, ask the router owner to reserve the server address so the connection kit stays valid. Use the current address continues without a router reservation; that address may change later and require LAN setup to be refreshed.
  3. Follow the displayed certificate and Windows Firewall approvals. Setup limits sharing to the selected private network.
  4. When the sign-in page opens, sign in as the administrator. Keep the server window open and the laptop powered on, plugged in and awake.

If a question was closed, reopen START_HERE.cmd in the same folder and choose shared access to retry. Completed account, certificate trust and verified firewall steps are reused.

3 · JOINING WINDOWS COMPUTERS

Connect in the browser

  1. On the server, open Setup Center and download the browser connection kit. You can also copy its generated LAN_CLIENT_KIT folder.
  2. Transfer and extract that complete kit on each joining computer. Double-click CONNECT_TO_CSD.cmd.
  3. Compare the displayed certificate fingerprint with the server owner's copy. If they match, choose The fingerprints match - connect.
  4. Sign in with an account created on the server. The administrator can create staff accounts in User Management.

Use the normal Windows browser opened by the kit and bookmark its sign-in page. Certificate approval is once per Windows account for this server certificate; it is not needed at every sign-in. Embedded app browsers may use a different trust store. Joining computers need only the connection kit. Their browser uses the records on the server; installing another server would create separate records.

4 · FIRST-USE CHECKS

Prepare for attendance

  1. As administrator, follow Setup Center to configure programs and locations. Under Cameras, choose Add camera, select its room, enter its connection and Save changes. Saving does not test the camera; use Test saved camera separately. Create staff accounts, a class and its schedule.
  2. For the first-use check, register a consenting participant, complete the required approval, and add them to the class roster.
  3. Open Recognition Tuner on the server. Check the picture and recognition under the actual lighting and distance. Keep normal matching selected for the first check.
  4. Confirm an enrolled participant is recognized correctly and an unenrolled volunteer stays unknown. Then test a scheduled attendance session, review its record and open Reports.
  5. Use Network and System Diagnostics to check connections and resource use while the joining computers operate the system.

A fresh installation contains no students or classes. Camera distance, group size and performance depend on the actual camera, lighting and laptop; check these before using automatic recognition for real attendance.

Daily use and data

Start
Double-click START_HERE.cmd on the server and choose its usual launch mode. After their first connection, joining computers can open a bookmark of the server sign-in page in the same browser.
Finish
Finish attendance in the app before closing the foreground server window. Optional automatic startup has separate Start / Stop controls.
Back up
Use System Operations and agree with the owner where protected backups and the matching recovery keys will be kept off the server. The current backup action is manual.
Manage cameras
Use Camera inventory to search and edit saved devices, and Room coverage to find rooms needing setup. Ready permits use but does not prove a working connection. Use Inactive or Maintenance to take a camera out of attendance use, or Retire to preserve its history. Review removal explains whether an unused camera can be deleted.
Update later
Keep this installation. Use Update or recover only with a supported update package supplied by the system owner. Never extract a fresh installer over your records. The included publisher public key verifies update packages; it is not a Windows Authenticode signature or proof of release approval or target-computer qualification.

If something stops setup

Another computer cannot connect
Check the server is running and awake, both devices use the same trusted local network (router or configured switch-only subnet), and the kit belongs to this server. Choose Check connection again.
The address changed
Reconnect to the original network and retry. If the router or server address really changed, keep the installation intact and ask the owner to reconfigure its connection.
A certificate warning appears
Use the complete kit and compare fingerprints again. Do not bypass a warning or mix kits from different servers.
An error remains
Keep the folder intact. Send the owner the complete error message with passwords and private data hidden. You can reopen the same installation in Use on this computer mode while the connection is checked.
